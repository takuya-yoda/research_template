# (案件名) 要件定義



## 目的・要求
<!-- 開発の目的，成果物に求めるもの．research_plan.md の対応項目を添える -->
- （例:蔵書検索）蔵書検索を高速で行えるアプリケーションの開発
- （例:強化学習）CartPole を倒立させ続ける方策を強化学習で獲得する
- （例）research_plan.md の対応項目: 「やること」の◯◯



## 用語定義
<!-- 実装時のブレを未然に防ぐ．以降は定義した語のみを使う -->
- （例:蔵書検索）蔵書: ISBN・書名・著者名・出版年・所蔵の有無を持つ 1 レコード
- （例:蔵書検索）一致: 大文字小文字と全角半角を区別しない部分文字列一致
- （例:強化学習）エピソード: 環境の reset から，倒立失敗による termination または 500 ステップでの truncation までの 1 試行
- （例:強化学習）エピソード報酬: 1 ステップ存続ごとの +1 を 1 エピソードにわたって総和した値



## 機能要件
<!-- 入力に対して求められる出力．例外処理も含む -->
- （例:蔵書検索）書名・著者名・ISBN に対して，部分文字列が一致する蔵書の一覧を返す
- （例:強化学習）シードと総ステップ数に対して，学習済み方策・エピソード報酬系列・設定値を保存する



## 非機能要件
<!-- 可用性，性能・拡張性，運用・保守性，移行性，セキュリティ，システム環境など -->
- （例:蔵書検索）同時接続 100 件の条件下で 95 パーセンタイル 1 秒以内
- （例:強化学習）同一シードで再実行すると報酬系列が完全一致する



## 除外要件
<!-- 開発工数の肥大化を未然に防ぐ．作業中に迷い込みそうな隣接タスクを先に除外する -->
- （例:蔵書検索）貸出・返却の管理は行わない
- （例:強化学習）画像入力・連続行動空間は扱わない



## CLI/GUI・画面遷移図
<!-- 利用者が触る面を確定させる -->
（例:蔵書検索）GUI
```text
[検索画面] --検索語を入力して Enter--> [結果一覧] --行を選択--> [詳細画面]
     ^                                                            |
     +---------------------------- 戻る --------------------------+
```

（例:強化学習）CLI
```bash
python train.py --seed 0 --steps 100000 --out results/seed0/
# -> results/seed0/{policy.pt, rewards.csv, config.json}

python plot.py --in results/ --out results/curve.png
# -> results/curve.png（全シードの学習曲線）
```



## 受入基準
<!-- 各要件の充足を判定する具体的手順．書けない要件は検証不能とみなす -->
<!-- 通し番号 (AT-01, ...) を振り，design.md の「検証方法」「実装計画」から参照する -->
- （例:蔵書検索）AT-01: 蔵書10万件を投入し「夏目」で検索 → 著者名に「夏目」を含む蔵書が全件返る
- （例:蔵書検索）AT-02: 存在しない語で検索 → 空一覧と「該当なし」表示（エラーではない）
- （例:強化学習）AT-03: `--seed 0` で2回実行 → rewards.csv が md5 一致
- （例:強化学習）AT-04: 学習後の方策で100エピソード評価 → 平均エピソード報酬 ≥ 475
