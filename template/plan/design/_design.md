### FR-01 蔵書検索（例）

```
1. CSV を読む（isbn, title, author, year, available）
2. 正規化する（ISBN のハイフン除去，書名・著者名の全角半角統一，大文字小文字統一）
3. メモリ上の一覧として保持する
4. 検索語を受け取る
5. 正規化した書名・著者名・ISBN に対し部分一致で絞る
6. 1000 件を超えたら先頭 1000 件で打ち切り，打ち切りフラグを立てる
7. 一覧と打ち切りフラグを返す
```

### FR-02 学習実行（例）

```
1. 引数を検証する（seed が整数，steps が正整数，out が未存在）
2. 4 系統の乱数源を seed で固定する（Python / NumPy / PyTorch / 環境）
3. 環境と方策を初期化する
4. steps 回，環境と相互作用しながら方策を更新する
5. エピソード終了ごとに (episode, steps, reward) を蓄積する
6. 1000 ステップごとに直近 10 エピソードの平均報酬を stderr に出力する
7. 学習済み方策・報酬系列・設定値を out へ保存する
```

## 9. 異常処理方針

`記入: Claude` `引継想定の場合は記入` `派生元: 要件定義書 6 節の異常系`

<!-- requirements.md の異常系（FR-XX-a/b/c）を，実装方針に変換する．
     【原則: fail fast】異常はその場で止める．黙って既定値で続行しない．
     研究コードでは特に重要．続行すると誤った実験結果を正しいと信じることになる．
     【禁止】try: ... except: pass．例外の握りつぶしは原因追跡を不能にする．
     【留意】「コードで対処しない」と決めた異常も，決めたこと自体を記録する． -->

| 事象 | 由来 | 対処 | 実装方針 |
|---|---|---|---|
| （例）検索語が空 | FR-01-a | コードで対処 | 全件返す．例外を投げない |
| （例）該当 0 件 | FR-01-b | コードで対処 | 空 list と truncated=False．HTTP 200 |
| （例）1000 件超 | FR-01-c | コードで対処 | 打ち切り，truncated=True |
| （例）CSV 未投入 | FR-01-d | fail fast | 起動時に FileNotFoundError で終了コード 1 |
| （例）CSV に必須列が無い | データ定義 | fail fast | 起動時に検証．行番号と列名を stderr へ |
| （例）出力先が既存 | FR-02-a | fail fast | 上書きせず終了コード 1．既存を一切変更しない |
| （例）SIGINT | FR-02-b | 捕捉して正常終了 | それまでの報酬系列を保存して終了コード 0 |
| （例）未知の引数・非正整数 steps | FR-02-c | fail fast | argparse で検証．終了コード 1 |
| （例）ディスク書込失敗 | — | 対処しない | 例外をそのまま送出．回復はインフラの責務 |

### 例外設計

- 例外は捕捉する層を決める:（例）ドメイン層で送出し，cli 層でのみ捕捉して終了コードに変換
- 例外メッセージには**原因と，利用者が取れる行動**を含める
  - 悪い: `ValueError: invalid`
  - 良い: `--steps は正整数である必要がある（受領値: -1）`
